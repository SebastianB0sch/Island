## Status model

| Status | Meaning |
| --- | --- |
| `scripted` | A data script exists (`Effects/scripts/<id>.json`), or the card is part of the 137-card regression baseline and has a verified name handler in `DADuelEngine.cpp`. |
| `vanilla` | No effect text. Normal Monsters use generic rules; effect-free Fusions/Rituals use `fusions.json` / `rituals.json`. |
| `pending` | Effect text exists, but there is no data script or verified engine handler yet. |
| `unsupported` | The card cannot be represented yet. This is always an explicit release blocker. |

## How Tier 0 was identified

The current four decks in `Content/Data/decks.json` contain exactly **137 unique cards**. That union is the regression baseline and is assigned Tier 0. Of those 137, **110 names occur verbatim in `DADuelEngine.cpp`** (109 effect-bearing cards plus Harpie Lady, which is a Normal Monster); the other **27** are Normal Monsters or the effect-free Fusion Monster 319, handled by generic rules and `fusions.json`. The manifest therefore credits 109 `engine_cpp` scripts and 28 `vanilla` cards, with zero pending Tier 0 cards.

This is an attestation of the current C++ baseline, not a claim that those 109 cards already have data scripts. When A04 ports the handlers into the effect runtime, each one must move from `implementation=engine_cpp` to `implementation=data_script` without changing behaviour.

## Runtime and content blockers

1. **760 pending effect cards** remain (410 Effect Monsters, 280 Spells, 160 Traps, plus effect-bearing Fusions/Rituals). They are honest `pending` rows, not silent omissions.
2. **Tier 2 contains 1053 cards** because A06/A07 usage datasets (Shop/packs.json, Opponents, Puzzles, Decks, Exams) now reference most of the pool. 293 are covered and **760 are pending**. `audit.py` treats Tier 2 as informational in the baseline stage and as a hard gate with `--release`.
3. **Fusion 1156 UFOroid Fighter** is unresolved: its text mixes one named material with a generic `1 Warrior-Type monster` slot, which the current recipe model cannot express.
4. **Contact Fusion** (745, 747, 774, 775) and **Power Bond / Fusion Gate** are data-valid but not resolved by the current engine. A04 needs the primitives listed in `RUNTIME_INTERFACE.md`.
5. **Ritual procedures** are complete as data (22/22), but the engine currently resolves only Legendary Flame Lord. A04 must load `rituals.json` and support generic Ritual Summons.
6. Tier 0 is green only because the C++ name handlers still exist. The 109 `engine_cpp` rows are the regression contract for A04's refactor.
